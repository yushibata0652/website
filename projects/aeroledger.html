01 / OVERVIEW

Invoice review with human oversight

Manual invoice checks take time, while automatic approval can overlook unusual charges. AeroLedger demonstrates a workflow that clears routine cases and brings exceptions to a human reviewer. We developed the project as a team at HackMIT, MIT’s hackathon.

A working prototype

The demo uses public Our World in Data launch-cost data as a stand-in for procurement history. Launch vehicles and vehicle classes represent vendors and parts; this is a demonstration of the review workflow, rather than a production pricing model.

03 / ARCHITECTURE

Interface, workflow, and data

FRONTEND

Next.js & React

A TypeScript interface displays the invoice queue, baseline comparisons, and human-review panel. Sequential batch processing stops when an invoice needs a decision and continues after review.

API & ORCHESTRATION

FastAPI & LangGraph

The Python API processes invoices and resumes paused runs. Explicit graph steps and checkpoints preserve each invoice’s position while waiting for human input.

STRUCTURED DATA

DuckDB

Historical launch-cost data supplies reference baselines. A separate reconciled ledger records processed invoices and final decisions for an audit trail.

DECISION MEMORY

ChromaDB

Vector similarity over vendor and part names retrieves prior reviewer rules. Matching invoices can reuse an approval without repeating the review step.

04 / DESIGN DECISIONS

Explicit rules and resumable review

DECISION LOGIC

Transparent approval paths

The core workflow uses deterministic pricing rules and vector memory, without an LLM call in the decision path. Each invoice moves through named steps with an explicit outcome.

HUMAN INPUT

Keep progress while paused

LangGraph interrupts preserve a run until the reviewer responds. Resuming the same invoice connects the human decision to the original workflow and its ledger entry.

05 / OUTCOME

A complete demonstration of the review cycle

DEMO

Approval through escalation

The demo brings together batch processing, anomaly detection, human override, resumed execution, and reuse of previous decisions.

DELIVERY

Separate UI and API

The frontend was published as a static Next.js export on GitHub Pages, with the Python API hosted separately on Render.

NEXT STEPS

Production readiness

Further work would include real procurement data, durable storage, production authentication, and evaluation of memory matches before broader use.
