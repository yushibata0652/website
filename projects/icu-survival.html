01 / CONTEXT

THE ASSIGNMENT.

This was a University of Michigan machine learning course project focused on predicting ICU patient mortality from more than 12,000 time-series health records. The modeling problem started with messy, repeated clinical measurements rather than a clean table of ready-to-use features.

What the project tested

Data cleaning, feature engineering, linear and nonlinear prediction methods, model selection, and cross-validation on real-world-style time-series health data.

02 / PIPELINE

FROM RECORDS TO PREDICTION.

12,000+ ICU Records Time-series measurements contain missing, repeated, and unevenly sampled clinical values.
→
Feature Engineering Clean and summarize patient measurements into a consistent feature representation.
→
Model + Validate Train logistic-regression and kernel-based models, then compare them through cross-validation.
03 / MY WORK

WHAT I IMPLEMENTED.

PREPROCESSING

Data Cleaning

Processed clinical records into a form that could be used reliably by the downstream machine-learning pipeline.

FEATURES

Feature Engineering

Converted time-series patient measurements into structured features representing useful information about each patient.

LINEAR MODEL

Logistic Regression

Used logistic regression as an interpretable classification baseline for mortality prediction.

NONLINEAR MODEL

Kernel Ridge

Evaluated a kernel-based method capable of representing nonlinear relationships through similarity between examples.

04 / MODEL CHOICE

LINEAR VS. NONLINEAR.

LOGISTIC REGRESSION

A strong, interpretable baseline.

Logistic regression models the relationship between engineered features and the probability of mortality using a relatively simple decision boundary.

KERNEL METHOD

More flexible relationships.

Kernel methods can capture nonlinear patterns without explicitly constructing a large set of transformed features, but extra flexibility does not automatically mean better generalization.

05 / CHALLENGES

WHERE THE WORK REALLY WAS.

MESSY DATA

Patients are not measured uniformly.

Real clinical-style records contain missing and uneven measurements, so preprocessing decisions directly affect the information available to the model.

GENERALIZATION

Flexible models need validation.

Cross-validation was essential for comparing model choices without simply selecting the model that fit one training split best.

06 / RESULT

WHAT I DELIVERED.

12K+ Time-series ICU patient records processed for the prediction task.
2 Primary model families compared: logistic regression and a kernel-based method.
CV Cross-validation used to compare model and hyperparameter choices more reliably.
07 / POST-MATCH

WHAT I LEARNED.

PREPROCESSING

Data work is model work.

The quality of the engineered representation can matter just as much as the classifier chosen afterward.

COMPLEXITY

Flexible is not automatically better.

A more expressive method only helps when it captures useful structure that generalizes.

VALIDATION

Evaluate before you trust.

Cross-validation provides a much stronger basis for model comparison than performance on a single convenient split.
