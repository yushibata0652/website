PERSONAL PROJECT · 2026

FOCUS FEED.

A distraction-free Instagram experience designed to preserve messaging and social connection while adding deliberate friction before opening Reels.

JavaScript Chrome Extension Firebase Auth Firestore MutationObserver
FocusFeed ● ACTIVE
REELS BLOCKED DESIGNED FOR FRICTION.
01 / ORIGIN

WHY I BUILT IT.

I wanted to reduce the amount of time I spent mindlessly opening Instagram Reels without losing the parts of Instagram I actually valued, especially messaging friends. Instead of trying to remove Instagram entirely, I designed FocusFeed around adding friction to one specific behavior.

The product idea

Block Reels by default. When temporary access is genuinely needed, request permission from a friend and unlock it for a limited amount of time with a six-digit approval code.

02 / PROCESS

FROM IDEA TO WORKING FLOW.

01 / PROTOTYPE

Test the interaction.

Started with a lightweight local prototype to validate the request, approval-code, and timed access experience before building the extension.

02 / BLOCKING

Control Reels access.

Built a Chrome extension that detects Reels routes, redirects blocked navigation, and removes Reels-related interface elements.

03 / BACKEND

Connect real users.

Added Google sign-in with Firebase Auth and Firestore data for friend search, friend requests, and accepted friend relationships.

04 / APPROVAL

Make access temporary.

Added access requests, six-digit approval-code validation, and a timer that automatically re-enables blocking when the window expires.

03 / SYSTEM

HOW THE PIECES CONNECT.

Chrome Extension Detects Reels navigation, modifies the Instagram interface, and enforces whether access is currently allowed.
→
Firebase Handles authentication and stores friendship, request, and approval-related application state.
→
Approval Window Valid code → temporary access → timer expires → Reels automatically becomes blocked again.
04 / CHALLENGES

WHAT MADE IT INTERESTING.

DYNAMIC WEB APP

Instagram does not behave like a static page.

Navigation and interface elements can change without a full reload. I used a MutationObserver so the extension can react when Instagram modifies the DOM after the initial page load.

PRODUCT DESIGN

Blocking alone was not enough.

The more interesting problem was creating enough friction to interrupt an impulse while still providing a controlled way to regain temporary access when needed.

05 / RESULT

WHAT WORKS TODAY.

AUTH Google sign-in and user-specific application state through Firebase.
FRIENDS Friend-code search, requests, accepting requests, and friend-list management.
TIMER Temporary approved Reels access followed by automatic re-blocking.
06 / NEXT

WHERE I WOULD TAKE IT.

SECURITY

Harden the approval flow.

Add stronger expiration, rate-limiting, validation, and server-controlled authorization around approval codes.

UX

Polish edge cases.

Improve error states, timer visibility, friendship management, and the extension popup experience.

MOBILE

Explore a mobile strategy.

The current working implementation is a Chrome extension. Native iOS support would require a different technical approach and platform constraints.

07 / POST-MATCH

WHAT I LEARNED.

WEB SYSTEMS

Modern pages are constantly changing.

DOM observation and route detection are necessary when building on top of a dynamic single-page application.

BACKEND

State turns a prototype into a product.

Authentication, users, friendships, and approval requests made the project much closer to a real multi-user application.

PRODUCT THINKING

Friction can be a feature.

The goal was not to make access impossible. It was to create a deliberate decision between impulse and action.
