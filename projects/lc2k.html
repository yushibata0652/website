01 / CONTEXT

THE ASSIGNMENT.

This was a University of Michigan computer organization project sequence built around the educational LC-2K instruction set. Across multiple assignments, I implemented the software tools needed to translate, combine, and execute machine-code programs.

What the project tested

Low-level programming in C, instruction encoding, symbol resolution, relocation, object-file structure, memory layout, and understanding how source code becomes executable machine state.

02 / TOOLCHAIN

THREE TOOLS, ONE FLOW.

Assembler Reads LC-2K assembly, resolves labels, validates instructions, and emits machine code or object data.
→
Linker Combines object files, resolves global symbols, performs relocation, and builds one final memory image.
→
Simulator Executes machine code instruction by instruction while updating registers, memory, and program state.
03 / MY WORK

WHAT I IMPLEMENTED.

ASSEMBLY

Instruction Encoding

Parsed opcodes and arguments, converted assembly instructions into machine representations, and handled signed immediate values.

SYMBOLS

Label Resolution

Built symbol handling so labels could be translated into correct addresses and branch offsets.

LINKING

Relocation

Adjusted references when text and data sections from multiple object files were combined into a final executable layout.

EXECUTION

Machine State

Simulated instruction execution by updating the program counter, registers, memory, and control flow.

04 / SYSTEMS CONCEPTS

WHAT IT MADE CONCRETE.

SYMBOL TABLES

Names become addresses.

Labels are convenient for programmers, but executable code ultimately needs numeric addresses and offsets.

RELOCATION

Addresses depend on placement.

When object files move during linking, references must be patched so instructions still point to the correct code and data.

MACHINE STATE

Instructions change state.

The simulator made execution tangible by showing how each instruction changes registers, memory, and the program counter.

05 / CHALLENGES

WHAT MADE IT HARD.

EDGE CASES

Small address mistakes break everything.

Off-by-one errors, incorrect branch offsets, sign-extension mistakes, or mishandled relocation can produce output that looks almost correct while failing on specific programs.

DEBUGGING

Errors can propagate across tools.

A bug in assembly or linking can appear later as a simulator failure, so debugging required tracing symbols, addresses, and machine state across several layers.

06 / RESULT

WHAT I DELIVERED.

07 / POST-MATCH

WHAT I LEARNED.

ABSTRACTION

High-level code rests on layers.

The boundary between source code, object files, machine code, and processor state became much more concrete.

DEBUGGING

Systems bugs demand precise tracing.

Instead of guessing, I learned to follow addresses, symbols, and state transitions until the incorrect assumption surfaced.

FOUNDATION

It changed how I see software.

Understanding translation and execution at this level made later systems and backend concepts easier to reason about.
